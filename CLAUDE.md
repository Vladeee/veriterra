# Project rules

Brand system for the holding company GukoV Group and its four companies: Vibija (fertilizers), Verdo (farm and food), Vaya (eco-glamping) and Viva (construction). Right now it is one presentation link with five landing pages. Real websites come later, in this same repo.

**Names vs ids.** Renamed at the user's request: VITREEONE → GukoV Group, Veriterra → Vibija, Vita → Viva. Names live only in `brand/brands.js`. The ids stay the old working names (`vitreeone`, `veriterra`, `vita`): `data-brand`, landing ids and hashes (`#veriterra`), `--fig-<id>-*` / `--bgpick-<id>-*` tokens, `landings/<id>.css` and saved choices all use them. Do not rename ids unless the user asks.

**Stage: working draft, skeleton.** The user wants it minimal and built step by step.
- **One link for everything: the root `index.html`.** It opens **straight on the presentation** (the intro screen with a Welcome button was removed at the user's request). Five landing pages: GukoV Group (the holding) plus Vibija, Verdo, Vaya and Viva, then a last page, **All variants** (`#overview`, menu item "All"): every Figma variant as a tile in a grid, grouped by landing; a tile opens its landing in that variant. Its **Invert all** button inverts (or restores) every landing at once; tiles show each landing's invert state. A compact top menu (`--nav-height: 3rem`, links at `--text-label`, medium, from the left page margin; the current page at full strength, the others at `--opacity-muted`) switches between them via the URL hash (`#verdo`; no hash or an unknown one opens the first landing, GukoV Group). The menu has no fill. **The arrows** (`.page-arrows`) belong to the Vibija deck: previous / next slide as a pair in the bottom right of the canvas (right edge on the grid, centred in the `--deck-pad-bottom` room under the slides, so they never touch an edge; the user asked for room from the edges); there are none on other landings. Once the page scrolls, a **progressive blur** fades in under it (`.topnav__blur`: five stacked backdrop-filter layers with masks, after wondersauce.com), so there is no hard edge.
- **Focus: Vibija only** (the user's request). The other four landings stay one screen: the logo screen (`.logo-hero`: wordmark + caption). Vibija has no logo screen (removed at the user's request).
- **Target for now: 1920×1080 only** (the user's request). Sizes are fixed rem values tuned for that screen; iPad and phone are not checked until the user asks again (hard rule 6 is on hold for layout, tap sizes still apply).
- **Grid: four columns.** `--grid-columns: 4`, `--page-margin: 3rem` (48 px), `--grid-gutter: 1.5rem` (24 px): columns of 434 px at 1920. Slide headers and bodies are grids on it (`.slide__head`, `.slide__body`); lists that sit on columns use `grid-template-columns: subgrid`. Put everything on the columns.
- **Type: three faces by role, no capitals** (the user's choices). Everything reads **roles**, never a face by name, so changing a face is one line in `tokens.css`: `--font-display` and `--font-logo` = **Andika** (main face: display, headline, logos; Regular), `--font-body` = **Lexend Deca** (secondary face: subheads and body text; Regular), `--font-annotation` = **Inter** (only the presentation's own captions, not part of the brand). Weight roles: `--weight-heading` and `--weight-text` (Regular), `--weight-annotation` (Medium). All self-hosted (`brand/fonts/andika/`, `lexend-deca/`, `inter/`, latin, OFL, from Google Fonts) and preloaded (Andika 400, Lexend Deca and Inter variable). One scale of size / leading pairs on the 1920×1080 canvas (tokens `--text-*`, `--leading-*`): display 160/152 and headline 80/88 (Andika), subhead 32/40 and body 20/30 (Lexend Deca), label 15/20 (annotations); plus specimen 112/118 and the logo-slide wordmark `--text-mark`. Tracking tightens with size (`--tracking-subhead` −1%, `--tracking-headline` −2%, `--tracking-display` −3%). `text-wrap: balance` on headings, `pretty` on text. Never `text-transform: uppercase` or wide letter-spacing. The logos too: every variant (`--fig-*-font` = `--font-logo`, `--fig-*-weight` = `--weight-heading`, case none, `--tracking-headline`); a variant keeps only the colours of its Figma frame.
- **Annotations (one look):** everything that explains the deck rather than shows the brand (the menu, section headers, terms like "Who" or "Our promise", face names, Hierarchy specs, swatch tables, proportion labels, combination captions and ratios, counts, the All variants captions) uses the class **`.anno`** (in `presentation.css`): Inter 15/20 Medium, normal tracking, tabular figures. Two strengths only: full for titles and names, **`.anno--quiet`** (`--opacity-muted`) for descriptions, specs, terms and counts. Annotation elements carry no font rules of their own; new captions get `.anno`, never a new style.
- **Vibija is a click-through brand book, minimum viable brand (MVB)**, shown at meetings on 1920×1080, laid out after a brand-guideline template the user sent. Ten slides, one per screen. Brand core on the dark scene: **01 Idea**, the cover (the logo lockup top left; a field of lime dots in cols 3–4 fading to the bottom left; "Every greenhouse, its own formula." at display across the grid; a footer on a hairline: "Our promise" col 1, the promise cols 2–3, a note col 4), **02 Who for** (a headline, then Who · What they need · What Vibija does · Why Vibija, one per column, each term opening with a small lime dot; the body keeps `--space-9` of air below). Visual base on paper: **03 Logo** (the lockup at `--text-mark`, centred in the space; four rules below on hairlines: sign, space, name, colour), **04 On colour** (eight grounds, 4 × 2 with captions: primary row Paper, Aubergine, Lime, Ink; quieter row Neutral 100 with an Aubergine 40 sign, Paper with a Lime deep name, Lime 20, and monochrome Aubergine on Aubergine 10; the colours are inline `--ground`, `--word`, `--sign`), **05 Typography** (the three type slides merged at the user's request: Andika on a Lime panel in cols 1–2, Lexend Deca on an Aubergine panel in cols 3–4, each with name and role, "Aa" at `--text-glyph`, alphabet and figures at subhead size, designer), **06 Hierarchy** (on the dark scene: spec in col 1, sample in cols 2–4 for display, headline, subhead, body; the display sample in the accent; the specs name the face and weight, update them when a face changes), **07 Primary palette** (Aubergine base, Lime accent, Paper ground, Ink text: a swatch with name, role, RGB, HEX, and below it four tones, dark to light), **08 Neutrals** (the 50–950 ramp with each step's contrast on Paper and on Ink, then what each range is for, one per column), **09 Status** (Success, Warning, Danger, Info: soft panel with base text, solid chip, bright on Aubergine, each with its measured contrast), **10 Themes** (light in cols 1–2, dark in cols 3–4: a fragment of the site, then its roles with token names and measured contrast). The user asked for colour on the slides ("boring without colour"): it comes from the palette as grounds and the sign (lime dots), never from new hues or textures. Interview facts: fertilizer for greenhouses, an individual approach, eco; purpose and character are still open, so "Why we exist" and "Character" are left out. Every slide opens with a section header (`.slide__head`: hairline, title col 1, description col 2, count `01 / 10` col 4 from `data-count`, all `.anno`, on one baseline). The header never moves between slides (no `data-reveal` on it; only the body rises in). Earlier versions (a 20-slide scroll book, scroll slides, Comfortaa capitals, the orange square, the 6-slide skeleton) were rejected; git history has them.
- **Deck mechanics** (`presentation.js`): a landing with `.slide`s is a deck (`html.has-deck`, no page scroll). **Canvas:** the deck is a 1920×1080 picture: `html.has-deck` sets the root font size to `--deck-rem` (min of 100vw/120 and 100dvh/67.5, = 16 px at 1920×1080) and each `.slide` is a fixed `--deck-width` × `--deck-height` (120 × 67.5 rem) box centred in the window, so every slide scales as one at any window size and nothing reflows; the menu keeps to the canvas width. `goTo(i)` shows one slide (`.is-current`; the others `inert` + `aria-hidden`), stops at the first and last slide, writes the slide id to the hash with `history.replaceState` (`#vibija-palette` opens slide 07; `#veriterra` opens 01), replays the reveal (`data-reveal`, `--i`, `.is-in`) and blends the sky. Keys: ←/→, ↑/↓, space / shift+space, PageUp/PageDown, Home/End; the edge arrows link to the previous / next slide id. Slides cross-fade (`--duration-slow`). `initSlides()` fills swatches from `data-swatch` (colour, `[data-rgb]`, `[data-hex]`, `data-on` light/dark text by luminance) and every contrast, never typed: `[data-contrast]` = the element's text on its own background, written to its `[data-ratio]` with a grade; `[data-ratio-on="--token"]` = a colour (`data-ratio-of`, or the swatch it sits in) on that token. Ratios are rounded down (4.49 shows 4.4).
- **Background (sky), after the user's reference** (a soft horizontal gradient; grain left out on purpose): the slides are transparent; behind them one fixed `.slide-sky` (inside the landing, `data-scene-prefix`). One structure everywhere, **linear only, no radial shapes**: `linear-gradient(to right in oklch, edge 0%, body ~30%, body ~58%, light 100%)` plus a soft shade rising from the bottom in the edge colour; the body widens a little with deck progress `--p`. Each slide names its scene (`data-scene`); a scene is three palette colours, tokens `--color-vibija-scene-<scene>-{edge,body,light}`: built from the theme roles: **core** (slides 01, 02 and 06, dark theme) = Ink → dark `bg` (Aubergine) → dark `raised`, **paper** (03–05 and 07–10, light theme, barely visible) = light `bg` → light `bg` → Neutral 50. On every step `blendSky()` mixes `--from-*` (last scene) into `--to-*` (new one) with `--mix` 0→100% over `--duration-reveal`, instant under reduced motion. Text follows the theme roles (`data-tone`, see the next point).
- **Vibija colour system** (tokens `--color-vibija-*` in `tokens.css`, for the deck now and the site later; the user's decisions: Aubergine is the base, Lime the accent, light and dark themes, neutrals and statuses). Everything derives from four anchors, Paper, Ink, Aubergine, Lime, so changing an anchor re-colours tones, ramp, roles and slides. Aubergine (hue 305) and Lime (122) are near complements: **tones mix an anchor toward Paper or Ink in OKLab, never Aubergine with Lime** (that mix is muddy). Tones: `aubergine-{10,20,40,70}` and `lime-{10,20,50}` (the anchor's share in a Paper mix), `lime-deep` (Lime's hue and chroma at 48% lightness, for text and icons on light). Neutrals `neutral-{50…950}`: Ink into Paper at 4–97%, so every grey keeps a trace of aubergine; 600 is the lightest that passes AA on Paper. Statuses `success`, `warning`, `danger`, `info`, each `base` (text on light, AA on Paper and on its soft), `-soft` (background behind base), `-bright` (text on dark, AA on Aubergine): one lightness and chroma, hues 150 / 70 / 25 / 255 (success cooler than Lime, so it never reads as the accent). Roles a site reads, `light-*` and `dark-*`: `bg`, `surface`, `raised`, `text`, `muted`, `border`, `primary`, `on-primary`, `accent`, `on-accent`, `link`, `focus` (light: Paper ground, Aubergine primary, Lime accent; dark: Aubergine ground, Lime primary and accent). Targets: text, muted and button labels ≥ 4.5, focus ≥ 3; borders are decorative.
- **The deck lives by its own colour system** (the user's request: "make the slides on the principles they describe, from the backgrounds to the arrows"). In `landings/veriterra.css` one block maps the theme roles to `--ui-*` (`bg`, `surface`, `raised`, `text`, `muted`, `border`, `primary`, `on-primary`, `primary-hover`, `accent`, `on-accent`, `link`, `focus`, `success`): light slides take `--color-vibija-light-*`, dark slides `--color-vibija-dark-*`, and so does `body` (from `body.nav-on-dark`) for the menu and arrows, and the two site fragments on the Themes slide. Slide text = `text` (Ink on light, Paper on dark; the logo stays Aubergine), quiet captions = `muted` (Neutral 600 / 300, not opacity), hairlines = `border`, focus rings = `focus`. Menu: current page `text`, others `muted`. **Arrows are the site's buttons:** next = primary (Aubergine with Paper on light, Lime with Aubergine on dark; hover one tone toward Paper, `--color-vibija-*-primary-hover`), previous = secondary (outline in `text`, hover `surface`). Measured: worst muted 5.6 (dark muted on the raised edge of the sky), arrow labels ≥ 6.7.
- **Logo lockup** (`.vb-lockup` in `landings/veriterra.css`): the sign, then the name (`data-brand-name`) in the display face, `--tracking-headline`. The sign is `brand/logo/veriterra/mark.svg`, a **placeholder solid circle** (the user's request, until a sign is drawn), used as a CSS mask on `.vb-sign`, so replacing that one file replaces the sign everywhere in any colour. Sized like a round capital of Andika: `--logo-sign-size` 0.75em, `--logo-sign-drop` −0.016em (the overshoot below the baseline), `--logo-sign-gap` 0.2em. Colours: `--word` and `--sign` (defaults `--ui-text` and `--ui-accent`); **the sign always takes another colour than the name, unless the logo is monochrome** (the user's rule). The **dot pattern** (`.vb-dots`, `--pattern-dot-step`, `--pattern-dot-radius`) is drawn from the sign: accent dots on a grid, faded by a mask.
- **Vibija palette = the only colours of the deck** (so changing the palette changes the whole deck; colours and fonts are still to be replaced). Tokens `--color-vibija-*`: primary Paper, Ink (near-black aubergine), Aubergine, Lime (the logo colour); secondary Lavender, Violet, Plum (aliases of `--bgpick-veriterra-*`, the full range lilac to aubergine). Scenes, swatches, panels and combinations are built from these names only; quiet text is the text colour at `--opacity-muted`; **every hairline** is `--brand-rule` = the text colour at `--rule-opacity` (25%, never above 50%). Theme roles in `[data-brand="veriterra"]`: `--brand-paper`, `--brand-ink`, `--brand-deep`, `--brand-on-deep`, `--brand-night`, `--brand-rule`, `--brand-font-display` (= `--font-display`), `--brand-font-text` (= `--font-body`), `--brand-word-tracking`. **No orange.** Shared slide styles: `.slide*`, `.slide-sky` in `presentation.css` (read only `--brand-*` and the JS-set variables); Vibija parts: `.vb-*` in `landings/veriterra.css`. Copy is a working draft.
- **Baselines on the grid:** where a column-1 text pairs with content in columns 2–4, the row uses `align-items: baseline` so their first lines share one baseline: the section header, Idea ("Our promise" ↔ the promise), Hierarchy (spec ↔ sample, every row), the swatch tables (name ↔ value). Check new rows the same way.
- **Page colour:** `syncPageColour()` paints `html` and `body` in the open landing's own colour, so overscroll on iPad or a resized window never shows the default paper around it.
- **Layout:** `.page-grid` in `presentation.css` is the same four-column grid for sections outside slides.
- **Logo animation:** the whole word rises with a blur and a bottom-up fade mask, then the caption fades in. It replays when the landing opens and when the variant changes.
- **Logo size:** every wordmark has the same letter height, whatever its font: `sizeInk()` measures how tall the letters stand above the baseline and scales the font size to `--logo-ink-height` (tokens). `fitWidth()` scales a long word down on narrow screens. `--fig-*-size` is only the starting size.
- **Logo centring:** the wordmark sits on the optical centre of the screen. Equal room above and below it; `centreInk()` in `presentation.js` measures the glyphs (canvas `measureText`) and sets `--ink-shift`, so the ink of the letters is centred, not the line box; then `--logo-optical-lift` raises it slightly. Do not use `text-box-trim` (Port Lligat's metrics break it).
- **Caption:** one short line of copy per landing in Inter Medium, sentence case, `--text-body`, pinned to the bottom of the screen. Dark (a deep shade of the logo colour) on light variants, the logo colour on dark ones.
- **Logo tracking** is tuned per variant (`--fig-*-tracking`), not copied from Figma: lowercase and bold display faces slightly negative, caps positive, light-on-dark a touch looser. Trailing tracking is pulled back with a negative right margin so the word stays centred. Kosugi Maru has monospaced Latin, so its variants carry `kern: true`: `kernInk()` wraps each letter and gives every glyph the same side bearing measured from its ink.
- **Figma style variants.** Each landing keeps only the frames the user picked from the Figma file (figma.com/design/kijHOH1H9UUlT26sK0ccT1): GukoV Group 1 ("Water · Faculty Glyphic"), Vibija 1 ("Aubergine · Inter": lime on aubergine, the brand book's colours), Verdo 1 ("Lime · Varela Round"), Vaya 3 ("Sky", "Sunrise", "Lavender", all Faculty Glyphic), Viva 1 ("Stone · Momo Trust"). Everything else was dropped at the user's request (git history has it, including Vaya "Blend" and the two-tone Vibija). The wordmarks of Vibija, Verdo, Vaya and Viva are set in capitals (`case: uppercase`, caps tracking); GukoV Group is mixed case, exactly as written. Names in the menu stay as written in `brands.js`.
- **Look of each landing** (`DEFAULTS` in `presentation.js`, fixed: there are no controls any more and choices saved on a device are not read, except the variant chosen from an All variants tile and the invert state): GukoV Group Mist; Vibija Mist on the Aubergine background with the "Brand tint" logo (pick-5); Verdo Flat with the "Same hue" logo (pick-1); Vaya Flat with "Same hue" (pick-1); Viva Flat.
- **Background gradients:** `data-gradient` on the landing picks **dawn** (default), **dusk**, **horizon**, **mist** (faint horizontal bands: one multi-stop `linear-gradient(in oklch to bottom, …)` of translucent white, ink and `--brand-streak` tints, 8–16%), **aurora**, **silk**, **tide**, **veil**, **prism** (complex light after paypath.ai on `.glow::before/::after`: curved ribbons from thin rings of huge ellipses, vertical curtains, rays from below; blurred, drifting slowly, stronger on dark pages) or **flat** (the Figma frame as is). Everything is translucent, so a Figma gradient background shows through. The drifting round blobs were rejected as ugly and too loud. The wordmark gets an equally faint vertical tint (`background-clip: text`), none on flat. No textures or noise ("looks dirty").
- **No switcher** (removed at the user's request, with its keyboard shortcuts and colour picker). The look is set in `DEFAULTS`; to change it, edit that and the tokens.
- **Backgrounds:** a landing can take a background colour from `--bgpick-<landing>-<id>` (`bgpick` in `DEFAULTS`, set as `data-bgpick`). Vibija uses Aubergine; the seven purples (lilac, lavender, mauve, iris, violet, plum, aubergine; OKLCH hue 285–320) are shown on its Colour slide. A pick replaces the variant's page and background, the automatic logo colour becomes light or dark by contrast, and it applies to the normal colours only (inverting ignores it).
- **Logos are not editable** (the font-tester typing was removed at the user's request).
- **Logo colours:** `applyColours()` in `presentation.js` builds `--v-bg/page/ink/ink2` from the variant, invert and `data-ink` (auto = the Figma colour, light, dark, pick-1…pick-5). The suggestions are recipes in `tokens.css` (`.landing[data-v-tone]` blocks, OKLCH relative colour syntax on `--v-page`): same hue, complement, two split complements and the brand tint; deep on light pages, pale on dark ones.
- **Menu** shows each brand's `name` (or its optional `menu` field) from `brands.js`.
- **Menu** turns light over dark logo screens and dark slides (`body.nav-on-dark`). On a deck it takes the current slide's `data-tone` in `goTo()` (sampling under the menu would still see the outgoing slide during the cross-fade); other landings sample `data-tone` under the menu.
- **Fonts:** Andika (headings, logos), Lexend Deca (text) and Inter (annotations) are the only faces in use and the only ones preloaded; `loadFonts()` waits for the logo face before the letters are measured. The other files in `brand/fonts/` (Andika Bold, the old Figma logo faces) stay for later but are not used.
- Reduced motion stops the drift and shows everything at once.
- There is **no style guide** for now (removed at the user's request). Sections are added **one at a time, only when the user asks**; right now only on Vibija.
- Colours, typefaces and copy are placeholders. Read `brand/BRIEF.md` before any brand decision.

## Hard rules

1. **Tokens only.** No CSS outside `brand/tokens.css` may contain a hex or rgb/hsl colour, px/rem/em length, duration, cubic-bezier, raw font-family or raw box-shadow. Use `var(--token)`. If a value is missing, add a token (CSS and JSON) instead of hardcoding it.
   - Allowed exceptions: `@media` breakpoint values (sm 40rem, md 48rem, lg 64rem, xl 80rem), colours inside `*.webmanifest`, `<meta name="theme-color">`, SVG and PNG asset files.
   - Escape hatch: end a line with `/* lint-ok */`. Only for technical, non-visual values (for example the 1px of a visually-hidden helper), never to skip a design decision.
2. **Change tokens in one commit:** edit `tokens.css`, then run `python3 tools/tokens.py sync`, then run `python3 tools/tokens.py check`. `check` must pass before every commit.
3. **Theming goes through `data-brand`.** Ids: `vitreeone`, `veriterra`, `verdo`, `vaya`, `vita`. Components read only the `--brand-*` variables (`--brand-accent`, `--brand-accent-strong`, `--brand-accent-soft`, `--brand-on-accent`), never brand primitives like `--color-veriterra-600`. Each landing carries its own `data-brand`.
4. **Static only:** HTML, CSS and vanilla JS. No npm, bundlers or frameworks. Everything must work on GitHub Pages and from a plain local server.
5. **Relative paths everywhere** (`../brand/tokens.css`, never `/brand/...`). The site is served from `vladeee.github.io/veriterra/`.
6. **iPad first:**
   - Every interactive element is at least `var(--tap-min)` (44px).
   - No hover-only interactions. Hover styles go inside `@media (hover: hover)` and must have a tap equivalent.
   - Test portrait and landscape.
   - Respect `env(safe-area-inset-*)`, use `dvh` for full-height layouts and `touch-action: manipulation` on controls.
7. **Accessibility:** text meets WCAG AA (4.5:1, or 3:1 for large text), `:focus-visible` is always visible, `prefers-reduced-motion` is honoured (tokens already collapse durations).
8. **Imagery:** never present an AI-generated image as real. Real photographs, clearly labelled visualisations, or neutral placeholders only.
9. **Public repo:** no financials, investment figures, land deals or legal or ownership structure in any file.
10. **Content language: English.** The user talks in Russian or English; answer in the language they use.

## Workflow

- **Claude Desktop (local session):** `.claude/launch.json` lists a `veriterra` server (`node tools/serve.js 5180`), so the preview panel shows it with a play button. Press it, or open http://localhost:5180/. Needs only Node. Work happens on the local files, nothing is pushed until the user says so.
- **Cloud session: preview inside Claude, not on localhost or GitHub.** Run `python3 tools/preview.py OUT_DIR` (OUT_DIR in the scratchpad), then publish `OUT_DIR/index.html` with the Artifact tool, passing the printed file list as `files` and `root` = OUT_DIR. It is a private Artifact that opens in Claude's own viewer. To update it, rebuild with the same OUT_DIR and publish the same file path again (the URL stays). The Artifact page is built from the repository, which stays untouched.
- **Do not push to GitHub until the user says the result is good** ("push", "залей"). Commit locally in small steps, run `python3 tools/tokens.py check` first, and push the branch only on that go-ahead. Never open a pull request unless asked.
- Preview locally with `python3 -m http.server 8000` from the repo root only when the user is on their own machine.
- Adding a block to the landings (only when the user asks): while the focus is on Vibija, add slides to the Vibija deck only (`.slide` with `data-scene`, `data-tone`, a `slide__head` with `data-count`; parts in `.vb-*`); later, when a block is meant for all five, add it to every landing in `index.html` with the same classes. Add only the components and tokens it needs.
